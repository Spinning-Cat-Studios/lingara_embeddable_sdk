## v0.3.0-alpha.1 — 2026-11-04


Generated from Lingara API 2026-10-dauntless-hoopoe (development) at spec backend@897aae2fcf74cebd19aa9ccf9dd116bc2c3a043f.

### Added

- `bevy_lingara`: `NpcDialogue::stored(dialogue_id, npc_id, target_lang, level)` loads a dialogue saved on Lingara by its store id, with `with_display_name` for the name shown before it loads; the core's `DialogueLoaded` and `DialogueLoadFailed` now reach the entity as typed Messages (a failed load is retried on the next `LingaraConnect`) (ADR 3.11.26f §5)

- `lingara-dialogue-ir`: `dialogue.v2` (ADR 3.11.26g). Named `endings` (1–8, one namespace with the checkpoints and `abandoned`); an NPC's steering stance, `disposition { suggestibility, initiative }`, read as bands by `disposition::Stance`, and `steer_to` on a checkpoint; and the procedural kind, a `ProceduralSpec` the planner fills with five atoms, a `PlanFragment`, a deterministic `procedural::expand` into an ordinary static graph, and `procedural::within_spec` / `within_spec_restored`. `load_document` reads either kind into a `Document`; `validate_with(&Document, Strictness)` refuses on save what a load warns. `version::write_schema` is the one write rule: a document v1 can say is still written as `dialogue.v1`, byte-identical
- Every kit: a story's outcome is the ending's id, so a graph ends in the story's own words (`DialogueEnded { outcome: "fled" }`); `ABANDONED` / `is_abandoned` (Rust), `DialogueOutcome.Abandoned` (C#) and `"abandoned"` everywhere else name the one built-in ending. The Rust, C# and GDScript builders gain `ending(id, label)` (ADR 3.11.26g §11)

### Changed

- **Breaking** — every kit: the outcome type is now a string, the ending's id, not a closed `success` / `failure` / `abandoned` enum. `EmbedEvent::DialogueEnded.outcome` and `GraphSnapshot.outcome` (Rust, the C ABI's message schema, the JVM kit's UniFFI record), Bevy's `DialogueEnded.outcome` (no longer `Copy`), C#'s `DialogueEnded.Outcome` and `GraphSnapshot.Outcome`, and Unreal's decoded `Outcome` all carry the id. A caller that matched on the enum compares the string instead; a saved snapshot still reads (ADR 3.11.26g §11.3)
- **Breaking** — `lingara-dialogue-ir`: `IrError` gains `rule: Rule` and `Warning` gains `code: WarningCode`, the words Backend publishes, so a refusal maps to its wire rule; `NpcProfile`, `Checkpoint` and `DialogueIr` gain the v2 members. The crate now warns `outcome_unreachable` ("no ending reachable") for a graph no path ends, as Backend already did
- The core refuses a procedural dialogue on `dialogue_load` with `invalid_input` "this kit cannot run procedural dialogues yet: upgrade lingara-embed", and logs once at `info` that a static v2 graph's stance loads but is not sent yet (ADR 3.11.26g §9)
